| Platform owner | The operator of the whole installation | role `superadmin` |

| Class teacher | The teacher responsible for a class | `classrooms.classTeacherId` or `classroomAssignments.role='class_teacher'` |

## Rules by area

The status of each rule is Verified, with its evidence, unless marked otherwise.

### Accounts

1. **A school role must belong to a school.** An account without a school gets 403 on every API (`apiAccessGate.js`, line 39).
2. **Unapproved accounts cannot sign in or use a token** (`auth-controller.login`, `authMiddleware`).
3. **Signing out or resetting a password ends every existing session** (`sessions_valid_from`).
4. **Passwords for admin-created accounts are generated by the server** (12 characters) and shown once (`adminController`).
5. **Admins cannot delete admin accounts**, nor accounts of another school (`adminController.deleteUser`).

### Classes and courses

6. **A class needs a class teacher** from the same school (`classroomController.createClassroom`).
7. **The same grade and section cannot exist twice in a school** (409).
8. **Courses and fee structures need a class first.**
9. **A course is created for at least one class.** The course, its classes and its enrolments are saved together or not at all (`courseClasses.createCourseWithClasses`).
10. **A selected student must be a member of one of the chosen classes**, and of the same school.
11. **A course keeps at least one class.** Removing the home class moves "home" to another assigned class (`courseClasses.removeCourseClass`).
12. **Removing a class from a course removes only the enrolments that class created.**
13. **Unticking a student of an "all students" class turns that class into "selected students".** Students who join the class later are then not enrolled automatically (`courseClasses.setClassEnrolment`).
14. **A student who joins a class is enrolled in its "all students" courses only** (`courseClasses.enrollStudentInClassCourses`).

### Access

15. **Course access needs enrolment.** Class membership alone gives no access to a course, its content, its tests or its lectures.
16. **A teacher acts only on courses they mentor.** Being class teacher gives no access to another teacher's course.
17. **A course teacher sees only the class's students enrolled in their courses**; the class teacher sees the whole class.
18. **Records of another school answer 404**, the same as missing records.

### Content and assessment

19. **Certificate eligibility:** every chapter of the course is completed, and the course has at least one chapter.
20. **Legacy quiz timer:** 1–1440 minutes, the end after the start. Students see published quizzes only, with one attempt each.
21. **AI test:** a new test needs a class and a course the teacher mentors that is taught to that class. Its audience is the class's students enrolled in the course.
22. **AI test attempt resets:** at most 3 per student per test. History is archived. Unpublishing is refused once attempts exist (module README; enforced in `AssessmentService`, Documented + partly Verified).

### Attendance and results

23. **Attendance:** no future dates; status `present` or `absent` only; only students of that class; one row per student per class per day (saving again updates it).
24. **Results:** at least one subject with marks; maximum marks greater than 0 and from the allowed totals; marks not above the maximum.

### Live lectures

25. **Start or schedule only for a course the teacher mentors that is taught to the class.** Admins do not start lectures.
26. **Scheduling:** at least 1 minute ahead and at most a year ahead; stored in UTC; duration 10–480 minutes.
27. **A scheduled lecture can be started from 30 minutes before its time.** Nothing starts automatically.
28. **Joining:** the teacher, or an enrolled student of the class, while the lecture is live. Students are never moderators.
29. **Attendance:**
    - at least 60 seconds counts as attended;
    - "missed" is set only after completion;
    - a lecture with no events at all is "unknown".
30. **A lecture is never deleted.** "Delete" cancels it. Closing a tab never ends it.

### Fees

31. **Online payments answer 503 while the gateway is not configured.** This is the current decision.
32. **An offline fee payment needs an idempotency key, a positive amount, a valid stage and a valid method.**
33. **A student reads only their own fee records.**

### Notifications

34. **One notification per recipient per event** (unique `dedupeKey`). The audience is worked out on the server, and the click target is decided by the client.

## Contradictions noticed

| Topic | Implementation | Elsewhere |
|---|---|---|
| AI module migrations | The local database has `aia_*` tables up to migration 010 | The module README says 001–008 are "not applied to the live DB" |
| Deleting a class | The handler deletes nothing and answers success | The UI and API name suggest a deletion |
| Database engine | SQLite only | `USE_POSTGRES` and PostgreSQL multi-tenant files exist |
| Platform-owner login | Reads a `superadmins` table | The local database has no such table; tests use `users.role='superadmin'` |
| Live class "delete" | Cancels and keeps the row | The older UI called it delete |
